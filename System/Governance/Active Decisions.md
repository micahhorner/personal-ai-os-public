# Active decisions (compact)

Why the system behaves the way it does — one line each, newest first. The
architecture spec's amendment log holds the change history; this file holds
the standing rules.

- **DEC-121 (product)** — **Wave 5 turns high-risk mutations into separately bounded transactions and corrects the documentation where the old abstraction hid durable state.** `System/Logs/` is a mixed-state directory: ordinary reports may be disposable, but `freshness-log.jsonl` is durable append-only history and `freshness-ledger.json` carries live obligations whose deletion forgives pending work, so the directory may never again be described or deleted wholesale as generated state. `aios generate` publishes three separate atomic domains in order: a complete `System/Generated/` candidate, the tool-owned `aios-*` projection inside `.claude/skills/` while preserving foreign entries, then one compare-and-swap commit of the freshness registry and ledger after re-proving the earlier inputs. A failure refuses or restores the current domain; it does not claim one cross-filesystem atomic swap. Protected command batches are review-bound: the read-only plan names the exact policy and write set (or, for upgrade, every exact semantic input), and apply requires `--apply --confirm --review-sha256 <fresh hash>` with commit-time reproof; `--confirm` alone is not authority for changed or expanded bytes. Bare `aios upgrade <release>` is read-only and creates neither checkpoint nor candidate. Because migrations and generation materialize its final candidate only after approval, upgrade labels its bounded limitation honestly: exact semantic inputs are reviewed, final output bytes are not yet materialized, and the journal pins the resulting full-tree identities for recovery. Direct-file privacy remains compliance, not confinement: these stronger transactions prevent path substitution, partial publication, and stale approval inside the CLI, but they do not sandbox a runtime that already has native filesystem access. No schema migration; system release remains **1.64.1**. *(v1.64.1)*

- **DEC-120 (product)** — **Recovery version 1.64.1 separates release identity from shared core identity and closes the core/PMM license boundary.** The owner approved `personal-ai-os` as the core `system.distribution_id` and `pmm-engine` for PMM Engine. Every migration binds an exact `source_distribution`; absent, unknown, or different values refuse before transforms, so two products sharing `system.id`, `instance_role`, a version, or a baseline cannot take each other's legal edge. Personal AI OS core and already-open packs remain MIT. PMM retains the exact existing proprietary personal-use license, including paid consulting use, attached inside `Packs/pmm/`; its manifest must point to that attached file before any root transition. No novel sale, redistribution, sublicensing, or service terms are drafted — those require owner/counsel wording. The core legacy-license transition accepts only the known legacy SHA-256 or the already-correct MIT SHA-256 and blocks every unknown modification. Security support is 1.64.1 only, contingent on tagged qualification evidence. *(v1.64.1)*

- **DEC-119 (product)** — **Personal AI OS is free and open source under MIT, and the system stops describing itself as something you buy.** The owner's ruling of 2026-07-28 replaces DEC-010's all-rights-reserved licence and the per-person grant added 2026-07-12. **MIT was chosen over Apache-2.0 for one reason: the product was already carrying two licences at once.** `LICENSE.md` forbade redistribution while the original add-on source and the shipped `obsidian-bases` pack were MIT, so a user reading the root file and a user reading a pack got opposite answers about the same folder — and Apache would have kept the split while adding a patent grant nobody had asked for. **The stale claims were load-bearing, not cosmetic.** §1.5 of the constitution said *"the pricing reflects it: the system is delivered by an implementer"*, and the constitution governs where any other document disagrees, so that sentence outranked the corrected README and would have been what a runtime resolved against; the README told the reader their copy *"comes from your implementer"*. **The Implementer role survives; the exclusivity does not** — installing, migrating and handing over is still real work someone may want done for them, and the audiences table is unchanged. `LICENSE.md` is now the canonical MIT text and nothing else, after GitHub reported the licence as `Other`: its detector matches the body within a small tolerance, and a *"your content is yours"* clause plus a history note more than doubled the file, so a project whose whole pitch is that you can take it was showing no licence at all to every tool that looks. Both moved to the README's Licence section, where they are likelier to be read. Adds `SECURITY.md` — whose scope deliberately includes **the governance prose itself**, because in a system where an AI runtime obeys documented rules, a rule that can be read to permit what it should forbid is a vulnerability with no code in it — and `CONTRIBUTING.md`, carrying the four-command local gate and the baseline-refresh step a contributor will otherwise trip over. **Two things are deliberately not done.** DEC-028's *"commercial legal packaging is out of v1 scope"* stays as written: the item is moot, not retroactively wrong, and §4.8 forbids editing a dated entry to match a later ruling. And **the repository stays private** — an MIT grant on a released version is irrevocable for that version, so publishing is a separate, owner-only act, and branch protection (free once public, absent today) should be enabled the moment it is. Documentation and licensing only; no schema change, no migration, no new command, no behaviour change. Constitution 2.21.2→2.21.3, a patch because the only change to it is §1.5's delivery sentence, with twenty derived documents re-stamped and each confirmed unaffected by a full-tree search returning zero hits. *(v1.64.0)*

- **DEC-118 (product)** — **A citation standard that only says "name the author" leaves most of the ways a note goes wrong unaddressed.** `safe-write` required a named author, work and year, forbade "research suggests", and forbade invention. Every one of those held while a live corpus accumulated defects of a different shape entirely, found by auditing it against primary sources: a thinker cited for the position he spent a career rejecting; a framework deployed in its originator's own vocabulary without ever naming him, so the claim could not be checked or followed back to the literature that qualifies it; a metaphor borrowed from economics whose mechanism has no counterpart in the domain it was carried into, making the analogy decorative rather than explanatory; a study measuring attention cited for a claim about reward, which looks like evidence while supplying none; and three figures with no primary source at all, each a round number attributed to "studies", each quoted most often by parties selling the remedy it justified. **The last category is the one that ends a piece on contact, and it is small and findable.** Added: say what the thinker actually argued and mark the extension; credit the framework you are using and say when it is contested; make a source's weight visible rather than listing a systematic review beside an aphorism; test that a borrowed analogy transfers before keeping it; distinguish what a study measured from what the claim needs; put effect sizes in the sentence, because "X drives Y" and "2.3 per cent per unit" are different claims and only one lets a reader judge the mechanism. **Replication hygiene is now a sweep, not a list.** A standard recording disqualified claims governs nothing unless something checks the existing corpus for them — adding to the list is not the fix, finding the existing uses is — and a removed claim is recorded as removed rather than deleted silently, so the gap is not later read as an oversight and refilled. **Registers of claim** are separated, because treating them alike produces two opposite failures: an interpretive claim hedged into vagueness preserves neither honesty nor insight, while an interpretive claim dressed as a finding borrows a credential it never needed and inherits a replication dispute that was never about it — the correction is to let the claim stand in its own register, never to delete it. **Explanation standards** close the functional-explanation gap: an arrangement may not be explained by the interests it serves unless the selection mechanism is named, otherwise the weaker and defensible construction is that it *has the effect of* producing the outcome and nothing corrects it because nothing measures the loss. And a note that classifies people must state what a legitimate disagreement looks like, since a taxonomy in which the author's position is the only unlisted one has stopped making claims. Capability `safe-write` 0.7.0→0.8.0. Documentation-only; no schema change, no migration, no new command. *(v1.63.0)*

- **DEC-117 (product)** — **A knowledge note is written to be learned from, and a corpus is measured for convention rather than for defect.** The shipped note register told every instance that notes are *"denser, longer-sentenced"*, that *"stacked clauses are in-register here"*, and that once a user's corpus exists a runtime should *"measure it and let the measurements override the defaults"* — with nothing anywhere asking whether a reader could follow the result. Those three instructions compose into a loop with no exit: a runtime writes dense notes, measures them, reads the averages as a target, and writes to the target, so the mean never moves and every note passes every check. **This is not hypothetical.** It ran for months in a live vault whose owner reported the notes as *"dense and difficult to understand, not just academic sounding"*; a runtime rewriting that corpus under the same register reproduced the defect inside a single session, hitting 24.6 words a sentence and reporting compliance, because the numbers were the only checkable thing in the file. The register is replaced with one built around a single test — a competent reader who does not already hold the framework follows the note once, without rereading — and the clarity rules that serve it: developed paragraphs as the governing unit, break the sentence and keep the paragraph, unstack the sentence fusing several claims rather than shortening sentences generally, state plainly then qualify, define coined terms in their own sentence, a concrete within two sentences of every abstraction, sequence so each part is understandable when it arrives, restate at a different altitude but never the same one, a header roughly every 300 words carrying its claim in plain words, and the read-aloud test. **The correction that matters most is the measurement rule.** A corpus is evidence of what a user writes, not proof of what they want; measurement now scopes to convention — citation style, titling, how objections are handled, the user's own vocabulary — and explicitly never to sentence length, and where the measurements pull against clarity that is a finding to raise with the user rather than a licence to write notes they will struggle to read. **The outward-voice boundary is also corrected.** The prior text fenced off the whole voice card at the knowledge layer, which threw out the craft rules with the marketing: attention machinery (hooks, cliffhangers, scroll-stopping openers) stays out of a note, while cutting clutter, refusing padding, varying rhythm and reading aloud are about comprehension and hold in both registers. Capability `safe-write` 0.6.0→0.7.0; constitution 2.17.0→2.17.1, a patch because the only change to it is the §5 catalogue stamp for that capability, with twenty derived documents re-stamped and each confirmed unaffected on that basis. Documentation-only; no schema change, no migration, no new command, and no behaviour change for any note already written. *(v1.62.0; renumbered twice before merge — this estate's seventh and eighth numbering collisions. Both numbers were taken from `origin` before work began; main advanced five releases and six DECs during the session, and two other branches claimed the same pair independently. Checking origin at the start is necessary and demonstrably not sufficient.)*

- **DEC-115 (product)** — **The machinery stops failing on things that are not your work.** Two defects of one shape, each blocking a version bump over something no human authored. (1) `aios upgrade` runs `generate`, `generate` writes index files, and Obsidian — open and watching — re-saves its own `.obsidian/workspace.json` inside the same run; the DEC-109 integrity check read that as user content changing mid-run and refused the bump. Measured on all three live instances 2026-07-27: **three received the v1.59.0 tree, none could record it, same single cause** — the file was stable for 36 s while the vault sat idle and changed across a bare `aios generate`, and no script in `System/Scripts/` writes it. **No vault open in an editor could complete an upgrade.** `.obsidian/` is runtime application state this command has been declared never to touch since v1.0.4, so it was already outside the upgrade *surface*; including it in the *verdict* was the inconsistency. Three files are now named as the editor's own session state and excluded from the verdict — `workspace.json`, `workspace-mobile.json`, `workspaces.json`. **The guarantee is unweakened:** every other file under `.obsidian/` is user configuration and is still verified byte for byte, a real note changing mid-run is still a hard failure that names the file and points at the checkpoint, and a session-state file that does move is reported by name with its reason rather than silenced — all three pinned by test. (2) `aios pack-check` (v1.58.0) reported the product's own template convention as a defect: 19 `duplicate id 'note-<slug>'` / `'source-<slug>'` errors across a pack's 22 templates, when `System/Templates/` uses the identical convention — `procedure-<slug>` **twice** — and `aios dupes` is green on it. `validate` has exempted template placeholders since the id rules were written; `pack-check` re-derived the rules without that. **A template's placeholder id is not a malformed id, it is a template**, recognised by the two things the product already knew — the `<…>` grammar (an angle bracket is illegal in an id) and the `Templates` folder (factored out of `validate` unchanged). The rule now has one definition both readers call. **Not a blind spot:** a placeholder id *outside* a Templates folder is now an error this command never made before, real duplicate ids and type-prefix violations are untouched, and a placeholder never enters the pack id index. The remaining 12 errors were `unresolved wikilink [[]]` — a false description of a fill-in slot that names nothing; those are now reported as the empty slots they are, advisory on every role, while a link promising a note that does not exist stays an error. Verified read-only on the live instance that produced them: **31 errors → 0**. No new commands, flags, schemas, components or fixtures; unit tests 624→638. Additive; no migration.

- **DEC-114 (product)** — **Following the documented path is not a duplicate.** The system tells a user to capture a source, write the note that develops it, and cite the source by id; the note then carries the source's title, because that is its title — and `aios dupes` called it an ambiguity error. Measured on a lived-in personal instance: **25 title-collision errors, 24 of them that exact pair** — distinct ids, distinct `type`, distinct folders, bodies that differ, every note declaring `sources: [<the source's id>]`, and **zero accidental duplicates among them**. `dupes.py` was byte-identical from v1.30.4 through v1.55.0, so every shipped version reddened a vault for obeying its own ingest procedure. A title collision is now a **warning** when the colliding records are one **declared derivation lineage**: every record typed, ids distinct, `type` distinct, folders distinct, and the group joined into a single *connected* graph by its own `sources` / `derived_from` edges — the two lineage relations the Metadata and Relationship Dictionary defines, so `related` and `depends_on` earn nothing. Warning and not silence, on the DEC-084 precedent: a legitimate-by-design collision stays visible and never red. **The citation is required, and that is the load-bearing half.** The same vault held one cross-type collision that is *not* a derivation — a personal to-do list and an unrelated work capture both normalizing to "To Do", neither citing the other — and a rule keyed on differing `type` alone would have silenced a real collision to improve a number. It stays an error. Same-type collisions, same-folder collisions, duplicate ids, untyped members and undeclared pairs all remain errors, each probed by its own test. The change can only move a collision from error to warning, never the reverse. *(v1.59.0)*

- **DEC-113 (product)** — **Pack content is validated inside its own namespace, and a vault note may cite a pack id without erroring.** `Packs/` is pruned from the canon walk and **stays** pruned — a pack legitimately ships its own `README.md`/`CHANGELOG.md` and its ids are its own (DEC-061/DEC-067). But on a pack-heavy instance that left the majority of the markdown outside every mechanical check: measured live 2026-07-27, **446 markdown files, 165 scanned, 260 inside `Packs/` and never opened** — the client's entire messaging, enablement, intelligence, published-assets and wiki corpus. A green suite was evidence about the vault *around* the pack. Found by hand in that blind spot: 20 broken wikilinks live for a day, an invalid `type`, two invalid `subtype`s, an id/type mismatch, 3 duplicate titles, 34 files with no frontmatter, and **a fabricated attributed customer quote whose own remediation had concluded "exactly one file"** because the second copy was inside `Packs/`. New read-only **`aios pack-check`** reads every `Packs/*/` holding a `pack.yaml`, resolving each pack's ids, titles and links against *itself plus the vault*, in a separate pass; `iter_markdown` gains an optional `skip_dirs` parameter whose **default is unchanged** and which nothing else passes. **DEC-067 IS NOT REGRESSED AND THAT IS THE CRUX — coverage is not canon**: pack ids never enter the canon id space, `dupes` still never collides a pack README with the vault's, `validate` reports the same file count, and it is guarded by test (two packs plus the vault all carrying the collision pair and a duplicate id, staying clean) **plus a guard that fails loudly if anyone later removes `Packs` from the default skip set**. Severity is role-scoped per DEC-083 — errors on `generic-master`, warnings on a `personal-instance` (DEC-082) — with five classes **never** downgraded: parse failures, id grammar, duplicate ids within a pack, a pack claiming a governance `canonical_for`, and committed secrets. An id shared with the vault is a warning, never an error (a pack is entitled to its namespace), and missing frontmatter is a warning or nobody would run the check. Composed into `health`, so `certify` carries it, with warnings rolled up as one line. **It found a real defect on its first run**: the shipped `obsidian-bases` pack vendors kepano's `SKILL.md`, whose links to `references/FUNCTIONS_REFERENCE.md` our packaging had flattened — both dead, fixed by restoring the layout the vendored file expects and leaving that file byte-identical. **Cross-boundary citation** takes the spec's option (a): pack ids are a **secondary index** consulted only by the link resolver, so a vault note declaring `sources:` into a pack no longer errors — resolution is not membership, nothing is merged. With the §6.3 hardening: `aios pack --remove` now **refuses** when a vault note cites an id that *only* that pack defines, and names the citing notes; an id the vault or another pack also defines still resolves and is not a reason to refuse. Two separate items handled separately rather than folded in: `links.py:42` held filenames **with** their extension while the lookup used raw link text, so `[[Guide]]` and `[[Guide.md]]` returned opposite verdicts and the passing spelling bypassed the id/title check (its own fix, its own test); and `test_pack.py`'s comment claimed its fixture fails on a duplicate id, which DEC-067 makes impossible — it fails on the id/type-prefix rule, and the comment is corrected. *(v1.58.0)*
- **DEC-112 (product)** — **A pack update stops destroying the client's own work; a pack manifest declares which paths are the vendor's and which are the user's.** DEC-061's contract — *"install places the folder; update replaces it wholesale (no merge, no duplicate); delete removes it leave-no-trace"* — is correct for a pure vendor scaffold and **destructive for a content-bearing role pack**, which is now the commercial shape: once a client's vault is in use `Packs/<name>/` holds their messaging hub, sales enablement library, intelligence hub, published assets, drafts, voice profile and company config, and an update took all of it while reporting success. Uninstall was worse framed — "leave-no-trace" was written when a pack held nothing but vendor files and it reassured the person about to lose their corpus. `pack.yaml` may now declare a **`layout:`** block with three path classes: **`scaffold`** (vendor-owned — replaced on update, deleted on uninstall), **`workspace`** (user-owned — never read, diffed, replaced or deleted; seeded from the ZIP only when the declared path does not yet exist, so the vendor never re-seeds over content the user curated or deleted), and **`seed`** (vendor starter content decided per file, written only where that file is absent, the user's once present). **Longest declared prefix wins**, so a pack can carve a vendor folder out of a user workspace or the reverse; a path declared in two classes is refused rather than guessed. **BACKWARD COMPATIBILITY IS THE ACCEPTANCE BAR: an undeclared path is scaffold, so a pack with no `layout:` behaves bit-identically to before** — proven by the pre-existing wholesale-replace test, left unmodified. Silence must not read as *safety*, though: the plan the user approves now states which paths are protected, and says outright when a pack declares none. An edited scaffold file is **never auto-merged** — install fingerprints the vendor scaffold into `Packs/<name>/.pack-scaffold-baseline.json` (the DEC-074 mechanism scoped to a pack), and on update a file whose hash moved is kept with the incoming version written beside it as `<name>.incoming` and reported, which is DEC-073's rule for the core applied to packs. Uninstall now **evacuates** workspace and seed content to `90 Archive/packs/<name>-<date>/` preserving relative structure, naming what moved where; the guarantee that mattered (no vendor residue, a clean vault) is untouched, while removal can no longer take the user's work. `--purge` is the only route to the old destructive behaviour: asked for by name, still `--confirm`-gated, and it prints how many files it will take and how many of those are the user's. A manifest declaring `layout:` **must** declare `min_system_version: '1.57.0'` or newer and is refused otherwise — an older core does not understand the block and would replace the folder wholesale, and the version floor every core has always enforced is what stops it installing there. *(v1.57.0)*
- **DEC-111 (product)** — **Deliberate divergence is not an unresolved conflict, and an instance that customizes what it was invited to customize can still record that it upgraded.** `aios upgrade` refuses to advance `system_version` while any protected path is in conflict — right, and unchanged: a vault must never claim a version whose files never arrived. But "conflict" was doing two unrelated jobs, and only one is a reason to refuse. Measured live on three instances 2026-07-27: all three took v1.55.0's `System/` tree cleanly and **none could record it**. Two were correctly blocked by red gates (pre-existing duplicate titles; a stale composite census). The third, the green customized work instance, was **green on every gate — validate 0, links 0, dupes 0, health 0, 318 of 322 shipped files byte-identical — and still locked out**, because its two divergences were a customized `System/Runtime/Task Router.yaml` (permitted by DEC-073, which states the router is *never* auto-merged; normal per DEC-083) and the constitution's `docgen` censuses (regenerated against its own tree, which `docgen --check` **requires** and fails `health` without). The second is a closed loop — the gate demanded the regeneration, then called the result a disagreement. A protected-path conflict now blocks **unless it is accounted for**, by exactly three recorded routes: `sanctioned` (the product declares the path instance-owned and never auto-merged — today the Task Router), `derived` (the copies differ *only* inside `docgen` regions), and `accepted` (a human reviewed it and named it with the new repeatable `--accept <path>`). Anything else blocks as before. `derived` is deliberately strict because it grants a bump: the file must carry a real `docgen` region, everything **outside** the regions must be byte-identical — one edited sentence beside a census disqualifies the whole file — and an unreadable file is never derived. Nothing is merged, overwritten or skipped quietly: `--accept` keeps the instance's copy exactly as today, accounted divergences get their own heading in the upgrade report, and the manifest's `system_version` line carries the reason on itself, so a reader sees the version and its caveats without leaving the file. An `--accept` naming a path that is not in conflict warns rather than being ignored, so a typo cannot read as a resolution. *(v1.56.0)*
- **DEC-110 (product)** — **The portability check reads the whole folder, and states how much of it it read.** `aios okf-check` is the verifiable half of the product's open-format claim, and its default scope was the manifest's content directories alone. On a vault whose knowledge arrives through an add-on pack that is a verdict over almost nothing: measured live on a role-pack instance, **9 concepts reported CONFORMANT while 236 sat in `Packs/` and were never opened** — the buyer's entire working corpus, outside the guarantee it was sold under, with nothing in the output saying so. The default scope is now the content directories **plus the content of every installed pack**, derived as the *complement* of `vaultpaths.PACK_MACHINERY_DIRS` (the same shape DEC-109 used for the upgrade-integrity claim), so a pack's content folders are covered by construction and only its machinery and root files are outside — mirroring `System/` and the vault's own root files. The report now states its own scope before its verdict: per-tree coverage, each pack's contribution (a machinery-only pack reports `0`, so it reads as looked-at rather than skipped), and the concept count inside the verdict sentence itself, so the claim cannot be quoted without it. **DEC-061/DEC-067 are untouched and that is the crux — coverage is not canon.** This command builds no index; it opens each file alone against three rules, so there is no namespace to merge, `Packs/` stays pruned from `iter_markdown`, and a pack's `README.md` still never collides with the vault's. Guarded by a test with two packs and the vault all carrying the collision pair and a duplicate id: `dupes` green, canon id space clean, no `Packs/` path in the canon walk. The same live instance is now **not** conformant (62 violations, all inside the pack) — pre-existing, previously invisible, and reported rather than hidden. `--target` is unchanged. *(v1.55.0)*

- **DEC-109 (product)** — **A mechanism that reports more coverage than it has is worse than one that reports none.** Five defects of that shape, each confirmed against live source first, each closed with a seeded-failure test proved to fail against the pre-fix code. **(1) CI did not run on most working branches.** The hand-maintained push-prefix allow-list omitted the prefixes used by most active branches; that was measured against the active branch set rather than assumed. The failure was silent — an unlisted branch shows no red X, it shows nothing. Replaced with a **catch-all**, deliberately not a longer allow-list: a list of prefixes is a hand-maintained census of a set that changes whenever someone types a branch name (DEC-105's finding in YAML), and the two errors are not symmetric — a needless run costs a minute, an unchecked branch costs a release. A `concurrency` group makes repeated pushes run one matrix; push and change groups differ by construction, so a superseded push can never cancel a merge's check. **(2) `aios upgrade` proved a tenth of what it claimed.** Its content-integrity fingerprint walked `manifest.directories.content` + `.obsidian` + `Packs` — a hand-maintained list of a set the USER controls — and on the live work instance where this was found it verified **160 files of 1,641**, reporting *"byte-identical (160 files verified)"* while **1,102 files sat in seven content folders that instance had registered in its own `folder-registry.yaml`**. **Extended rather than narrowed, and the measurement decided it**: a full-tree fingerprint of that vault costs **0.11 s**, so verifying less had no argument behind it, and a narrowed claim would have left the real promise resting on nothing for 90% of the user's notes. The scope is now the **complement** of the upgrade surface rather than a list — a folder invented tomorrow is covered the day it is made — which also brought in three things the docstring had always promised and nothing had checked: the change journal, the certification records, and the user's root files. Verified read-only on the real vault at 1,294 files in 0.25 s. The report states its own scope and names the two regenerated folders it cannot cover. **(3) Every version claim except `system_version` was unaudited (GAP-4).** A **component-version truth key** now resolves a claimed version against the file declaring it (capability, agent, workflow, schema, this document, `vault_profile_version`), in the two shapes the corpus writes — the §5 catalogue stamp and inline `` `name` X.Y.Z ``. It immediately found **ten of the constitution's seventeen capability/agent stamps stale**, `safe-write` by four minor versions; all ten corrected. Exempt because they are not claims about now: transitions, amendment logs, the register's dated figures, and dated provenance (*"Source: `safe-write` v0.2.1, shipped in v1.14.0"*). **What it cannot reach is printed in its own report every run** — external spec versions, dependency ranges, documents cited by title — because closing a false-coverage defect by building a second one would be a poor joke. **(4) `doc-paths` exempted the decision register wholesale (GAP-8).** `doc-audit` had already taken the right position on that file: counts exempt, behaviour checked. A path is not a count — it is a pointer, followed by whoever reads the entry, dead in any year — and the blanket exemption was hiding `System/Capabilities/manage-packs.md`, dead since DEC-070, in the entry that introduced the capability. Now checked (205 references, up from 168), with one narrow allowance: a path in a **sentence** that records the file's removal is skipped (sentence-scoped, never line-scoped — a register entry is one 900-word line), and **the count of what was skipped is reported**. **(5) The owner's given name was compiled into `measure.py`'s speaker patterns** — the hit DEC-106 reported unresolved rather than deciding. **Owner's ruling: make it configurable, not delete it**, because deleting it silently changes what a real transcript measures. The shipped vocabulary is generic; the user's own labels live in `80 User/transcript-voices.yaml` (the `vocab-guard`/`voice`/`authoring`/`handoff` hook pattern — loaded if present, defaults otherwise). Labels are escaped and shape-checked, a malformed file is reported and never fatal, and every run prints which marker set it used, since a config silently ignored is worse than none. **Also settled with evidence rather than opinion:** the Claude Adapter Guide's *"private stays out of its context entirely"* claim, reported both fixed and unfixed by two prior audits, **is fixed** on main — the live sentence says `private` does reach a hosted runtime, cites the profile keys as evidence, and carries a dated note of the old wording. Capabilities `ingest-and-connect` 0.16.0→0.17.0. Additive; no migration, no schema change, no new command. system_version 1.53.0→1.54.0; constitution 2.15.2→2.16.0, twenty stamped documents re-stamped.

- **DEC-108 (product)** — **A pack ZIP is a stranger's artifact: every malformed manifest reports, none raises — and the contract it is held to is a file.** Found by measurement, not by a bug report: read against the two real pack manifests in the estate, `aios pack`'s gate turned out to assume `resources:` is a mapping, while **PMM Engine declares a flat top-level list** and **Content Engine nests it under `components:`**. Installing a PMM-shaped ZIP raised `AttributeError: 'list' object has no attribute 'values'` — a traceback where a trust boundary owed a verdict. **Both shapes are canonical**, and the reasoning is that the gate never cared which one it was: its only question about a listed path is *does this exist in the ZIP*, the grouping keys are documentation, and nothing downstream consumes them — so refusing either would break a shipped pack in exchange for no safety. `components:` and `resources:` each now accept a mapping, a flat list, or a single string, top-level or nested.
