# Glossary

- **Adapter** — files that translate the system's rules for one runtime or app (Claude, Obsidian). Adapters point at rules; they never own them.
- **Agent** — a standing AI role with its own scope and permissions (this system ships three: Onboarding Guide, Steward, Extension Builder).
- **Approval** — a human's explicit sign-off on material for external use. **Editing an approved record means setting `approval` back to `pending` yourself** — nothing resets it for you, and no check reports an approval that outlived its content.
- **Archive** — inactive material kept out of default retrieval; reversible, unlike deletion.
- **Canonical** — the single authoritative version of a fact, rule, or record. Everything else references or is generated from it.
- **Change journal** — the append-only log of what changed, by whom, and why.
- **Checkpoint** — a restorable snapshot (Git commit or zip) taken before risky changes.
- **Classification** — sensitivity marking: public, internal, private, restricted.
- **Component** — a registered system part: capability, agent, script, template, schema, workflow, adapter, or operation.
- **Context compilation** — assembling the smallest complete set of notes an AI needs for one task.
- **Context engineering** — the field's term for controlling what enters an AI's context window for each task. Here the Task Router does it: it loads the smallest set of files a job needs (progressive disclosure), so everyday work stays fast and grounded.
- **Context store (owned)** — the field's name for where an agent's working knowledge lives. The distinction here: the store is plain files you own and keep across vendors, not data held inside one AI product.
- **Certification (`aios certify`)** — a one-command product-integrity pass: composes the mechanical checks with governance/safety, command idempotency, doc-truth, and the regression suite into one ranked record. Answers "is the product sound enough to ship?"
- **Docgen (`aios docgen`)** — regenerates hand-maintained enumerations (the command list, capability list, counts) into marked `<!-- docgen:KEY -->` blocks, from source. `--check` verifies them without writing and runs inside `health`, so a stale block fails the build. The generation half of what `doc-audit` polices.
- **Doc-audit (`aios doc-audit`)** — the documentation-truth gate: reads the real figures from source (commands, capabilities, principles, diagrams, the current version, and every **component version** a document states — capability, agent, workflow, schema, the constitution's own) and fails when a document disagrees. Where a version has no machine-readable source — an external spec, a dependency range — the gate says so in its report rather than implying coverage it lacks. Historical records (CHANGELOG, journal, amendment logs) are exempt, and the decision register is exempt from dated figures — they were true when written.
- **Doc-paths (`aios doc-paths`)** — the prose path-reference gate: every backticked vault path a document cites (`System/…`) must point at a real file. Covers the reference class `links` deliberately skips (backticks mean "literal text"). Only always-present `System/` roots are checked; placeholders (`<name>`, `NNN-…`), runtime-created folders, and historical records are exempt. **The decision register is not** — a count in a dated entry was true when written, but a pointer is followed by whoever reads it and a dead one is dead in any year. The one allowance: a path in a sentence that records the file's *removal* is skipped, and the report counts how many it skipped.
- **Contradiction** — two records that conflict; both are preserved and linked, never silently resolved.
- **Decay / review-due** — knowledge ages; each note can carry a date after which it should be re-verified. The date is *stamped by a command, not by the act of promoting*: `aios review-due --set-missing` writes today + the type's horizon from the freshness registry onto promoted notes that lack one, and `aios health` reports how many are still unstamped. Drafts, captures, and pre-feature notes never accrue review debt.
- **Freshness ledger** — the system's private fingerprint list (`System/Logs/freshness-ledger.json`): a checksum of every typed note's body, used to notice changes. Regenerable; deleting it re-baselines the vault and forgives pending triage — never corruption.
- **Grandfathered** — content that predates freshness enforcement (or arrived via import): it carries no ripple or review obligations until deliberately edited or promoted. Obligations are never retroactive.
- **Derived** — produced from other material and traceable to it via `derived_from`.
- **Enrichment** — processing new information for what it changes, connects, supports, or contradicts — not just filing it.
- **Frontmatter** — the YAML metadata block at the top of a note.
- **Generated** — rebuildable files (indexes, reports, the `.claude/skills/` Agent Skill projections). Never hand-edited; safe to delete.
- **Governance (AI governance)** — the rules constraining what an AI may read, change, or send. Concrete here rather than abstract: preflight, privacy classifications, protected objects, the change journal, and the kill switch.
- **ID (stable)** — a note's permanent name (`decision-2026-07-10-weekly-webinars`); survives renames.
- **Inbox / quarantine** — where new material waits, untrusted, until processed.
- **Import (vault import)** — bringing an existing external vault in via `aios import` and a written plan: dry-run first, human approval, checkpoint, one-time; the source is read-only. Two modes: verbatim (byte-identical) and mapped (transformed to system records).
- **Kill switch** — `ai_writes_enabled: false` in the manifest; stops all AI writes instantly.
- **Knowledge-note standard** — the shipped rules for how a knowledge note is written: a note is an *input* for future work, not an output — precise, densely cited, scoped, carrying a falsification condition and counterarguments. The user's `authoring.md` (in `80 User/`) and their existing corpus refine it; an AI model's house style is never the fallback. Lives in the `safe-write` capability.
- **Memory layer** — the industry term for persistent knowledge an AI reuses across sessions. Here it is your vault of plain files (ownable, editable, readable in any text editor) rather than an invisible vendor feature that ends with the subscription.
- **Migration** — a versioned, validated, reversible structural change.
- **Posture (coexistence)** — what happens to a user's old note system: gradual (default), side-by-side (permanently separate), or full adoption later. Recorded in the workstyle map; migration is offered once, never repeated.
- **Preflight** — the check every write gets first: does this exist? what does it affect? Depth scales with risk.
- **Protected objects** — files no AI may change without explicit instruction (rules, schemas, its own permissions).
- **Provenance** — where information came from; the chain from source to conclusion to output.
- **Runtime / runtime profile** — the AI model operating the vault, and the record of what it's certified to do.
- **Capability** — a written task-level procedure any runtime follows step by step; the fourteen core capabilities are safe-write, retrieve-context, ingest-and-connect, maintain-vault, recover, build-extension, import-vault, manage-packs, method-kit, session-handoff, manage-todo, start-project, record-decision, and adversary. A registered *component*, packaged as an Agent Skills directory (`System/Capabilities/<name>/SKILL.md`) so any skills-compatible agent can read it: it carries a contract, tests, and a diagram, and passes an activation gate. `aios generate` emits a spec-valid projection of each under `.claude/skills/`. Distinct from a **command** (below): a capability is a bigger, governed feature; a command is a small mechanical tool.
- **Command (`aios …`)** — a deterministic, script-level tool you *run* for a mechanical job — no AI judgment, identical every time — <!-- docgen:commands -->

Commands live in `System/Scripts/cmd/` and are the smallest, lowest-ceremony `script` tier of the component hierarchy (`script < template < workflow < capability < agent`); unlike a capability they need no contract, tests-as-a-peer, or diagram. Rule of thumb: a **command** is a thermometer you read; a **capability** is a governed feature the system performs.
- **Add-on** — an optional capability you install to extend your OS (e.g. a content engine, a role pack, a life-skill pack), distributed as a *pack*. Not part of core — add or remove it without a trace. Its `kind` is a manifest field. See `System/Documentation/Add-Ons and Packs.md`.
- **Pack** — the format an add-on ships as: a self-contained folder under `Packs/<name>/` carrying a `pack.yaml` manifest plus its components. `manage-packs` installs or updates only the exact reviewed archive, writes a hash-bound activation receipt, and removes through a reversible archive/quarantine/validate transaction; purge is explicit. An add-on is *distributed as* a pack; the two words are not interchangeable.
- **Source** — immutable captured evidence (document, page, transcript, or spoken recollection).
- **Sync boundary (`sync`)** — the storage switch: `sync: local-only` means the file never leaves this machine via git push, cloud sync, or hosted backup. Backed by a `.gitignore` rule (`aios validate` cross-checks marking and rule, both directions); a `Local Only/` folder implies it. Storage only — AI readability is `ai_use`, sensitivity is `classification` (DEC-092).
- **Ripple (`aios ripple`)** — the connected-knowledge check: when a note's body changes, every linked, referencing, and referenced live note is listed until the effect on each is judged and recorded (`--ack … --effect`). `makes-stale` marks a neighbor's status; prose is never auto-rewritten.
- **Stale** — flagged as possibly outdated because something upstream changed; not trusted until reviewed.
- **Decisions space (`Decisions/`)** — the dedicated top-level home for *your* decisions, kept alive by the `record-decision` route: one dated record per settled choice, id'd by dated slug (`decision-2026-07-25-annual-plan`), never numbered by hand. The register view (`System/Generated/index-decision.md`) is generated from frontmatter — newest first, grouped by project — so parallel decisions cannot collide. Distinct from `System/Governance/Active Decisions.md`, which is the *product's* register.
- **Supersede** — replace a record while preserving it as history.
- **Tacit knowledge** — context in your head, captured by voice or interview, always labeled with who said it and how sure they were.
- **Voice attribution** — the ingest rule for any multi-voice source (AI chat export, interview, meeting): measure who said what (`aios measure`), build the user's notes from the user's own claims, keep assistant material only where it's faithful to the user's meaning, and attribute or drop the assistant's own theses and coinages — never blend them into notes carrying the user's name. Lives in `ingest-and-connect`, step 3a; certified by fixture 16.
- **Open Knowledge Format (OKF)** — Google Cloud's open specification for storing knowledge as a folder of Markdown files with YAML frontmatter, currently **v0.2** (July 2026; v0.1 was June 2026). Conformance is three small rules, so your knowledge folders already are an OKF bundle as they sit on disk — `aios okf-check` verifies that, names the version it checked, and states its own scope (how many notes, which folders, which installed packs' content; pack machinery and `System/` are outside it). v0.2 added optional fields for provenance, trust, freshness and computation (`sources`, `generated`, `verified`, `status`, `stale_after`); AI OS emits the ones it can back with a real fact and leaves the rest empty rather than filling them in. Two OKF field names — `status` and `sources` — are also AI OS field names with different meanings, which is why `okf-export` translates them and `okf-check` mentions it.
- **Outcome families** — the four things a harvested finding can become, decided at ingest triage before anything is built: **Knowledge** (a note, new or updated), **Action** (a to-do/project item, routed to your own task list with the destination named), **Governance** (a call only you can make — surfaced, never made), or **Nothing** (dropped, with the reason recorded). Defined in `ingest-and-connect`, step 3t.
- **Manufactured corroboration** — the failure that intake-batch dedupe exists to prevent: the same claim, found in three "independent" sources and promoted as triply-attested, when it was reached once and pasted twice. It looks exactly like evidence, which is why nothing else catches it, and it lands in the knowledge layer the system exists to protect. Proven live: of four documents handed over as one corpus, one was 97% a paste-up of two siblings and shared no id, title, or alias with them. Measured by `aios dedupe-batch`; certified by fixture 27.
- **Intake-batch dedupe (`aios dedupe-batch`)** — the read-only check that compares the files arriving *together* to each other and reports a pairwise overlap matrix plus each file's unique contribution. **A report, never an action:** it never discards, because which copy is the fuller record is the human's judgment. Distinct from `aios dupes`, which compares records to **canon** (id/title/alias) and cannot see batch repetition at all. Once the human decides, `--annotate` writes the overlap map into the surviving sources' frontmatter — bodies stay immutable — so the next extraction counts shared material once.
- **Verified extraction (`aios extract`)** — how a `.docx` becomes vault text: convert to Markdown (heading levels, list nesting and numbering, emphasis, tables, images at their true position), then **prove it character by character** against the original's text-bearing paragraphs. A failed proof emits no Markdown at all — the original is filed to `Attachments/` with a pointer note naming the failure — because a partial conversion loses paragraphs invisibly. Whatever v1 cannot take (footnotes, endnotes, comments) is reported with a count, never dropped silently. An explicitly selected external source is read-only and is copied into contained vault outputs; its original path is never moved, deleted, or written beside. Certified by fixture 26.
- **Delta register** — the routing table ingest produces *before* any note is built: one row per finding — the claim in your words, its source line, whose voice it was, its outcome family, a one-line rationale, and a column for your ruling. Cheap decisions before expensive work: you review the map, and only what routed to Knowledge gets built out. Template: `System/Templates/delta-register.md`; certified by fixture 25.
- **Working material (`type: working`)** — project-layer files where the thinking happens: plans, logs, captures, drafts, scratch (the `working_subtypes`). Bound to the projects folder (+ Inbox/Archive) and deliberately light to type — id, dates, a summary, an honest status. First-class to `validate`; excluded from default knowledge search and surfaced by `aios search --project <Name> --domain <domain>`; the boundary holds both ways — asymmetrically: `working` in the knowledge folder is an error (new class, strict), while a knowledge-typed `note` in the project layer draws one rolled-up advisory warning, never an error (DEC-082: a lived-in vault never goes red on the user's own notes). Untyped project files stay legal — a gentle warning names this class, and nothing is ever auto-typed.
- **Workstyle map** — `80 User/workstyle.md`: how this user already organizes knowledge — their vocabulary, tags, rituals, machinery, and a binding never-touch list. Drafted by the AI from observation (with consent), confirmed by the user, consulted before filing or naming anything. Deleting it restores default behavior.
- **Vault** — this folder. Your knowledge plus the operating system that makes it usable.
