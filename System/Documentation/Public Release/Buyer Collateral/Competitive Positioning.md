## “ChatGPT or Claude already has memory and projects.”

Concede: they are convenient and require almost no setup. Distinguish: Personal AI OS keeps its working knowledge as files the user controls and can inspect, correct, back up, and move. Vendor products have their own changing export and portability features, so never claim a specific feature is absent without checking it at the time of use. **Demo:** open a local note, then run `aios okf-check` and read the scope line aloud.

## “I already use Notion, Coda, or Obsidian.”

Concede: these are useful places to write, organize, and collaborate. Obsidian is the product's recommended interface. Distinguish: Personal AI OS adds a tested operating layer around plain files: routing, written procedures, change review, validation, journals, checkpoints, and recovery. It can complement a notes app rather than replace it.

## “I could build this myself.”

Concede fully: the core is MIT-licensed, the files are readable, and a determined person can assemble their own system. A service buyer is paying for setup, migration judgment, tested procedures, and support, not access to a proprietary folder. Never use “months of work” as a universal estimate.

## “Isn't this just an AI pointed at Markdown?”

Yes. That is the substrate, and the lack of a proprietary runtime is deliberate. The product is the tested system around it: deterministic routing, written capabilities, note-level privacy rules, protected-write review, journals, checkpoints, validation, migrations, and recovery. Important limit: with direct native file access, the privacy and write rules are compliance controls rather than physical confinement.

## “Is the format really open?”

The **knowledge layer** is stored as an Open Knowledge Format v0.2 bundle. `aios okf-check` checks it locally and reports exactly what it inspected. Never say the whole repository is an OKF bundle; it also contains product code, tests, documentation, and fixtures.

The core can also emit marker-owned Agent Skills projections from its own capabilities. That packaging result is not certification, endorsement, or proof that every runtime has been tested.

## “Will another AI run it?”

The architecture makes the runtime replaceable and the v1.64.5 release ships Claude Code and Codex profiles. The shipped profiles remain formally `NOT CERTIFIED`, because the complete externally bound runtime battery has not been recorded. Say “replaceable by design,” not “works with any AI.”

## “Will vendors build this?”

Probably parts of it. Memory, projects, exports, and agent tooling will keep improving. The durable distinction is inspectable ownership: the working context and operating rules remain files the user controls. Do not speculate that a vendor is structurally incapable of offering portability.

## “Will it become slow or expensive?”

The system starts retrieval from compact indexes and opens selected records rather than loading the whole vault. Actual latency, token use, and quality depend on the runtime, model, request, vault, and host. Do not state a v1.64.5 performance result unless the exact target-bound release evidence supplies it. The retired 1,600-token claim must not be used.

## “Is it safe?”

Name the mechanism rather than using the adjective alone. Supported write paths use exact review plans, confirmation, safe-path checks, atomic transactions, validation, and rollback. Filtered retrieval enforces note-level privacy and domain rules. Direct-file runtimes are not OS-sandboxed and can technically open files their account can reach. Secrets never belong in the vault.

## Proof, stated at the correct scope

Any v1.64.5 qualification claim must cite evidence bound to the exact released tag and commit. Historical evidence may be discussed only with the version and scope visible; it is not evidence for v1.64.5. Product evidence is never a testimonial, customer-outcome study, human-usability test, or external runtime certification.

**Positioning line:** Personal AI OS combines user-controlled files with a written, tested operating layer for AI-assisted work.
